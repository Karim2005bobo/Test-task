# AutoResearch-агент для ML-задач (хакатон «Альфа Будущее»)

Запуск: `python solution.py` — единая точка входа. Агент сам читает условие и данные, строит решение,
улучшает его в цикле AutoResearch и пишет `submission.csv`.

## Архитектура
```
solution.py → agent/pipeline.py
  data.py      понимание задачи: тип (регрессия/классификация), метрика из условия, id/target из
               sample_submission, словарь признаков, выбор схемы валидации
  llm.py       OpenAI-совместимый клиент (Qwen), лимиты токенов/вызовов, парсинг JSON
  research.py  цикл: гипотеза (LLM или встроенная очередь) → эксперимент → оценка → keep/discard
  worker.py    эксперимент в дочернем процессе (таймаут, изоляция падений)
  features.py  рецепты признаков + код от LLM (AST-проверка, без доступа к таргету)
  models.py    LightGBM / CatBoost / XGBoost / sklearn-HGB
  metrics.py   RMSE, MAE, R², Macro/Weighted F1, Accuracy, LogLoss; подбор весов классов
```
Этапы: 1) анализ задачи LLM → 2) быстрый baseline LightGBM и **сразу** валидный submission →
3) AutoResearch (до 55% бюджета времени) → 4) дообучение лучших 2–4 пайплайнов на всём train,
жадный бленд по валидации, (для классификации) веса классов под Macro-F1 → submission.

## Ключевые решения
- **Честная валидация.** Если test лежит строго «после» train по периодному столбцу (здесь
  `Year_Factor`: train 1–5, test 6), валидация — прямая по времени (обучение на ранних периодах,
  проверка на последних); иначе — hold-out 80/20. Сплиты фиксированы на весь прогон, скрытый тест
  недоступен, код признаков видит только признаки (таргет утечь не может) — защита от подгонки метрики.
- **Универсальность.** Тип задачи, метрика, id и таргет определяются из данных/условия, без
  привязки к конкретному датасету.
- **Работает без LLM.** Если LLM недоступна/исчерпан лимит, берётся встроенная очередь гипотез
  (признаки, преобразование таргета, CatBoost/XGB, гиперпараметры). При невалидных ответах LLM
  агент переключается на встроенные гипотезы.
- **Бюджет.** Время: 3 ч на задачу, планирование до 88% лимита; submission атомарно перезаписывается
  после baseline и после блендинга, так что валидный файл есть всегда. LLM: `LLM_TOKEN_BUDGET`
  (150k токенов), `LLM_MAX_CALLS` (30) — укладывается в дневной лимит.
- **Память экспериментов.** История гипотез/результатов/ошибок передаётся в каждый запрос LLM;
  итог — `experiments.json` в рабочей папке.

## Переменные окружения (`agent/config.py`)
`DATA_DIR`, `OUTPUT_PATH`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`, `TIME_BUDGET_SEC`,
`MAX_EXPERIMENTS`, `AGENT_WORKDIR`. Контракт платформы зафиксирован в organizers' `baseline.py`
(в репозитории его нет) — имена переменных/путей нужно сверить и при необходимости поправить
только в `config.py`.

## Результаты локальной проверки (задача 1, регрессия, forward-валидация, без LLM, бюджет 15 мин)
baseline RMSE 45.54 → log1p-таргет 43.93 → бленд 42.79 (валидация на периоде 5).
